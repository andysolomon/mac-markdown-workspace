# Arch private PKGBUILD — overview

The `packaging/arch/` directory holds a **private** Arch x86_64 recipe for
the Mac Markdown Workspace. It complements (it does not replace) the
existing per-platform builders:

| Target | Builder | Output | Notes |
| --- | --- | --- | --- |
| Linux x64 ZIP | `bun run make:linux` | `out/make/zip/linux/x64/Mac Markdown Workspace-linux-x64-X.Y.Z.zip` | Reproducible build (issue #23) |
| Arch x86_64 | `./packaging/arch/build.sh` | `mac-markdown-workspace-X.Y.Z-x86_64.pkg.tar.zst` | This issue (#24) |
| macOS ZIP / Squirrel | `bun run make` (or via CI) | macOS dev artifact | Issue #23 deferred to macOS host |

## Why a separate Arch recipe

`pacman -U` is the path that the operator actually uses to install the
app on Omarchy. The native tool here is the PKGBUILD, not a Debian or RPM
spec. Reusing the existing `MakerDeb` / `MakerRpm` from electron-forge
would produce a `.deb`/`.rpm` that no Arch user could install cleanly.

## How the artifact flows

```
   ┌────────────────────────────────────────────────────────────────────┐
   │                  Local checkout (private repo)                     │
   │                                                                    │
   │   bun run make:linux  ──►  out/make/zip/linux/x64/<zip>           │
   │           │                       │                                │
   │           │ (SHA-256)             │ (rename + gh release upload)  │
   │           ▼                       ▼                                │
   │       packaging/arch/PKGBUILD ◄─── packaging/arch/release.sh       │
   │           │                                                        │
   │           ▼                                                        │
   │   packaging/arch/build.sh ──►  makepkg -si  ──►  .pkg.tar.zst       │
   └────────────────────────────────────────────────────────────────────┘
```

The SHA-256 of the source ZIP is committed into `PKGBUILD`. Any future
release update requires editing the SHA-256 in `PKGBUILD` *and* the
release tag — this gives an honest "this artefact, no other" boundary.

## What lives where

- `PKGBUILD` — recipe. Uses local-source pattern; the artifact is
  pre-staged by `build.sh` and validated against `sha256sums` by makepkg.
- `.SRCINFO` — generated by `makepkg --printsrcinfo` and committed so
  `namcap`/helpers can lint without re-parsing the recipe.
- `build.sh` — operator-side helper. Authenticates to `gh`, downloads the
  private release, verifies SHA-256, runs `makepkg -si` under `/tmp`.
- `release.sh` — operator-side helper for cutting a release: rebuilds the
  artifact, refuses to publish unless SHA-256 already matches the
  PKGBUILD (forcing a deliberate PKGBUILD bump), uploads to GitHub
  Releases with a SHA256SUMS manifest.
- `install-guide.md` — operator-facing private install instructions,
  includes the explicit "this is **not** the Omarchy AUR path" boundary.

## Security model

- No token is ever embedded in source URLs, scripts, or PKGBUILD metadata.
- SHA-256 of the ZIP is the integrity check; `gh` auth is the access check.
- `chrome-sandbox` is installed setuid-root (4755) so it works on kernels
  without unprivileged user namespaces; the binary is invoked at a fixed
  path under `/opt` so the launcher can always find it.
- User data lives outside the package's owned files (Electron stores
  notes in `~/Documents/Mac Markdown` and `~/.local/share/mac-markdown-workspace`),
  so `pacman -Rns` leaves it alone.

## Boundaries

- AUR publication is **not** done here. AUR requires anonymous source
  access and is a separate future decision.
- CI integration is **not** done here (belongs to issue #29).
- ARM64 is **not** claimed; the `arch=('x86_64')` field is intentionally
  restricted and validation logs say so.
- The package is **not** signed by a maintainer GPG key. Operators verify
  the SHA-256 against the public GitHub release publisher.
